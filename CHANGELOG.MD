# Changelog

## v1.2.0

Заголовки ответа, длительность вызова и хук после вызова. Сигнатуры существующих методов не изменились.

### Добавлено
- `HttpResponse.Headers` заполняется заголовками ответа (первое значение на имя, ключ — каноническое имя);
  раньше поле было всегда пустым — `Retry-After` и подобные не прочитать.
- `HttpResponse.Duration` и `HttpRequestBuilder.Duration()` — длительность вызова от начала `Do` до прочтения тела.
- `SetOnComplete(func(ctx, CallResult))` — хук после каждого `Do`/`GetResult`, в том числе при транспортной ошибке:
  метод, итоговый URL (с query — маскировать секреты в хуке), статус (0 — ответа нет), длительность, ошибка, тела
  запроса и ответа. Для журнала внешних вызовов и метрик без своей обёртки.

## v1.1.0

`gosdk-core` поднят до v1.1.0. API пакета не изменился.

### Изменено
- `gosdk-core` v1.0.29 → v1.1.0.

### ⚠️ Изменения поведения
- Требует gosdk-core v1.1.0: поднимать вместе с gosdk-http-core ≥ v1.2.0, иначе сервис теряет AppInfo
  (имя сервиса) в логах запросов и событиях Sentry.
- Логгер core экранирует управляющие символы: запись лога - одна строка; `logger.Dump` - одна строка JSON.

## v1.0.16

Минимальная версия Go поднята до 1.27.3. API и поведение пакета не изменились.

### Изменено
- `go.mod`: `go 1.26.0` → `go 1.27.3`. Причина - уязвимости стандартной библиотеки go1.26.0
  (`govulncheck`), исправлены в новых версиях Go. На go1.27.3 `govulncheck` уязвимостей стандартной библиотеки не находит.
- `gosdk-core` поднят до v1.0.29 (переход на Go 1.27.3, API не изменился).

### ⚠️ Изменения поведения
- Потребителю нужен Go ≥ 1.27.3: после `go get` этой версии в его `go.mod` станет `go 1.27.3`.
  С `GOTOOLCHAIN=auto` toolchain скачается сам; с `GOTOOLCHAIN=local` на Go < 1.27.3 или в образе
  без доступа к `proxy.golang.org` сборка упадёт - образ сборки `golang:1.27.3`.
